# Phase 0 — S3 (mode Produit) et F4-D (React 19, suppression de l'écran classique) (2026-09-25)

Lecture seule : aucun fichier modifié. F4-D est la bascule finale décidée depuis F4 : l'écran
classique (`app/routes/app._index.jsx`, 4 100 lignes, protégé jusqu'ici) disparaît, avec les tables
`calculations` et `calculation_annotations` (décision 18), la recopie `shop_plans` (R0-02) et React 18.
S3 (mode Produit du Simulateur, T2a) en fait partie : c'est l'héritier du calculateur.

## 1. Inventaire de l'écran classique : chaque fonction et sa destination

6 onglets, 20 actions. Ce qui n'a **pas encore** de nouvelle maison bloque la suppression.

| Fonction (onglet / action) | Nouvelle maison | État |
|---|---|---|
| Calculateur de marge unitaire (enregistre dans `calculations`) | S3 mode Produit « nouveau produit » | **à faire** |
| Simulateur prix minimum pour une marge cible (`simulateSellingPrice`) | S3 mode Produit + mode objectif S2a | **à faire** |
| Historique / Monitor des marges par commande (`order_margins`) | section Produits (liste par produit, CM2) — Profit plus tard | **à faire** (aucune section Explorer n'est livrée) |
| Alertes de calcul (`set_alert`, `margin_alerts`, violations sur `calculations`) | disparaissent avec le calculateur ; les seuils vivent dans Réglages > Objectifs | suppression |
| Audit catalogue Expert (`run_audit`) | Produits > Audit | **à faire** |
| Suivi des coûts : coûts par variante (`costs_save`, `costs_list`), import CSV (`costs_import_csv`), confirmation douane (`confirm_customs_category`) | **Réglages > Coûts produits** | **à faire — bloquant** : c'est la seule saisie des coûts produits (jalon d'activation « coûts renseignés ») |
| Réglages boutique (`set_vat_regime`, `set_shipping_model`, `set_default_country`, `set_fees`, `set_profitability_threshold`, `set_current_cpa`) | Réglages (R1, R2) | fait ; la recopie `shop_plans` et le trigger R0-02 tombent avec l'écran |
| Offres (`subscribe`, `subscribe_expert`, `billing.request`, `isTest` sur boutique de dev) | **Réglages > Offre** (logique de facturation reprise telle quelle) | **à faire — bloquant** (facturation intouchable : on déplace l'écran, pas la logique) |
| Recommandation IA (`ai_recommend`, Pro) | I1 « Demander » | suppression, retour en I1 |
| Opérations de sync héritées (`backfill_orders`, `recalc_estimated_margins`, `backfill_breakdowns`) | sync v2 (F2) | suppression |
| Annotations (`save_annotation`, Expert) | aucune (liées aux calculs) | suppression |

Consommateurs hors écran à adapter : le cron d'alerte de rentabilité (`api.cron.profitability`) et
`recalcEstimatedMargins.server.js` lisent le seuil dans `shop_plans` ; `plan.server.js` lit
`shop_plans.plan` (facturation, reste). `engine.js` (protégé) garde 16 consommateurs (crons, ingestion,
coûts, douane) : il reste, seul son appel par l'écran disparaît.

Tests qui touchent l'écran ou ses fonctions : `lot2_ui_labels` (libellés de l'écran), `invariants`,
`lot1_customs`, `lot21`, `lot22`, `lot24`, `lot26` (exclusions i18n, zéro diff) — à adapter ou retirer
au lot de suppression.

## 3. Arbitrages

**X1 — Séquencement de F4-D.** (a) Tout en un lot ; (b) par étapes : **D0** migration technique
(React 19, `shopify-app-react-router` 3, Node 22, react-router reste en 7), **D1** nouvelles maisons des
fonctions bloquantes (Coûts produits, Offre, mode Produit, Produits minimal + audit), **D2** suppression
de l'écran, des tables et de la recopie. Recommandation : **(b)** ; chaque étape est déployable seule et
l'écran classique reste la roue de secours jusqu'à D2.

**X2 — react-router 8.** (a) Dans D0 ; (b) lot séparé après D2. Recommandation : **(b)** (une montée
majeure à la fois).

**X3 — Réglages > Coûts produits.** (a) Porter `costsUi.jsx` et `customsUi.jsx` dans
`/app/settings/products` (liste par produit, panneau par variante, import CSV, confirmation douane),
traduits, formulaires natifs + barre de sauvegarde ; (b) réécrire. Recommandation : **(a)** : la logique
(`variantCosts.js`, `customsClassification*.js`, validations) est déjà pure et testée (lots 1, 5, 20) ;
seul l'habillage change. `data_fixed` explicite à la sauvegarde (S10).

**X4 — Réglages > Offre.** Page qui affiche l'offre courante (`plan.server.js`) et les deux boutons
d'abonnement, avec **le même code** `billing.request` (`isTest` boutique de dev, allowlist bêta).
Aucune modification de tarif ni de logique. Recommandation : la reprendre telle quelle, traduite.

**X5 — S3 mode Produit.** (a) « Produit existant » : le Simulateur sur les feuilles d'**un produit**
(`aggregate().byProduct`, déjà calculé) avec les mêmes leviers, l'objectif S2a (« quel prix pour 40 %
de CM2 sur ce produit ? ») et la mémoire ; « Nouveau produit » : calculateur unitaire (prix d'achat,
port, douane via `computeLandedCost` d'`engine.js`, frais, prix de vente → CM1 / CM2 unitaire, prix
minimum pour une marge cible par bissection), sans le « + 4,5 % » codé en dur, sans table
`calculations` (le scénario peut être retenu dans `decision_log`) ; (b) « nouveau produit » seulement.
Recommandation : **(a)** : c'est la décision 18 (« le calculateur devient un cas du simulateur »).

**X6 — Historique des marges par commande.** (a) Section Produits minimale (liste des produits avec CA,
CM2, CM2 %, unités, statut de coût, depuis `byProduct`) + Audit Expert dedans ; (b) pas de remplacement
(Aujourd'hui et Indicateurs suffisent) ; (c) liste de commandes. Recommandation : **(a)** : la vue
par produit est ce que les marchands consultaient ; la liste de commandes n'apporte rien de plus.

**X7 — Alerte e-mail de rentabilité.** Le cron reste ; il lit le seuil dans `shop_settings` au lieu de
`shop_plans` (D1) ; `margin_alerts` (seuil des alertes de calcul) est supprimée avec le calculateur (D2).
Recommandation : oui.

**X8 — Recommandation IA.** Supprimée en D2, réintroduite dans I1 « Demander ». Recommandation : oui,
en le disant dans le journal des changements.

**X9 — Suppression en base (D2).** Migration : `DROP TABLE calculations, calculation_annotations,
margin_alerts`, `DROP TRIGGER` R0-02, `DROP COLUMN` des colonnes de réglages de `shop_plans` (garder
`plan`, `updated_at`), `purge_shop` redéfinie sans ces tables ; rollback qui recrée tables et colonnes
**vides** (les données supprimées ne reviennent pas : sauvegarde Supabase préalable à faire par vous).
Recommandation : faire la sauvegarde, appliquer test → rollback prouvé → prod, comme toujours.

**X10 — Mise en garde.** D2 est irréversible pour les données de `calculations` (historique de
calculs manuels). Options : (a) les supprimer ; (b) les exporter en CSV par boutique avant (téléchargeable
dans Réglages pendant 90 jours) ; recommandation : **(b)** si une boutique réelle en a, sinon (a) —
à vérifier en lecture sur la prod avant D2.
