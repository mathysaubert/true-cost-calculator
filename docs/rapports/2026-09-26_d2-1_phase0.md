## 2. Découverte majeure : la documentation contredit l'essai D2-0

La page [Shopify App Pricing](https://shopify.dev/docs/apps/launch/billing/shopify-app-pricing) décrit deux régimes :
- **les apps inscrites avant avril 2026** gardent les anciens moyens ;
- **après le 28 avril 2026 :**
  - « Shopify App Pricing no longer sends webhooks for subscription changes » ;
  - « no longer appends `charge_id` to your redirect URL » ;
  - le moyen documenté pour connaître l'offre est `activeSubscription(appId, shopId)` de l'**API Partner**, complété par le paramètre `plan_handle` de l'adresse de retour.

| Point | Documentation (apps récentes) | Observé le 2026-09-26, app de test créée le jour même |
|---|---|---|
| `charge_id` dans l'adresse de retour | Plus ajouté | **Présent** (`charge_id=75694112982`) |
| Abonnements lisibles par l'API Admin (`currentAppInstallation`) | Présentés comme l'ancien moyen (« legacy Billing API queries ») ; `currentAppInstallation` n'est cité que pour les achats uniques des apps migrées | **Lisibles** (nom, statut, essai, historique) |
| Moyen documenté | API Partner `activeSubscription` | Non essayable : l'app de test (Dev Dashboard) est invisible pour l'API Partner |

**Conséquence.** Reconnaître l'offre par l'API Admin marche aujourd'hui, mais **ce n'est pas garanti par Shopify** pour une app qui passe à App Pricing en 2026. Le moyen documenté, `activeSubscription`, est disponible dans la version **2026-07 de l'API Partner, désormais stable** : `publicApiVersions` renvoie 2025-10, 2026-01, 2026-04 et 2026-07 avec `supported: true`, et unstable avec `supported: false`. Il demande la permission « Manage apps ». La vraie app, publique, y est visible (vérifié en D2-0).

La recommandation de D2-0 (« par nom, via l'API Admin ») est à **réviser** : voir W1.

## 3. Autres faits relevés

- **Plus d'API de facturation après l'activation.** « you can't create new recurring application charges using the Billing API. Don't call `appSubscriptionCreate` or framework billing helpers ». Dans le code, `requestSubscription` (billing.server.js) et la configuration `billing` de `shopify.server.js` (essais de 7 jours) sont donc à retirer.
- **Page d'offres :** `https://admin.shopify.com/store/:store_handle/charges/:app_handle/pricing_plans`.
- **Descente vers le gratuit :** « deferred… effective at the end of the paid plan's current cycle » (source : [Setup subscription charges](https://shopify.dev/docs/apps/launch/billing/shopify-app-pricing/subscription-billing/setup-subscription-charges)). En D2-0, pendant l'essai, Pro a été annulé immédiatement ; l'effet en période payante n'est pas mesuré. L'API Partner expose `cancelAtEndOfCycle` et `pendingUpdate`.
- **Migration des abonnés existants.** « Existing subscriptions keep billing through the Billing API until you move them ». Condition pour activer : au plus 8 plans publics et au plus 1 plan public gratuit. Le Partner Dashboard propose de générer des brouillons de plans depuis les plans existants. Un déplacement d'abonnement ne s'annule plus une fois effectif (source : [Migrating to Shopify App Pricing](https://shopify.dev/docs/apps/launch/billing/shopify-app-pricing/migrating-to-shopify-app-pricing)).
- **Plans privés :** en nombre illimité, et une boutique peut être autorisée sur jusqu'à 8 plans privés. Ils sont visibles uniquement par les boutiques autorisées (source : [Public and private plans](https://shopify.dev/docs/apps/launch/billing/shopify-app-pricing/plans)).
- **Relances d'impayés (dunning).** Le cron lit les statuts (dont FROZEN) dans `allSubscriptions`, via l'API Admin. Il dépend donc du même choix que W1. L'API Partner expose aussi des événements `SUBSCRIPTION_CHARGE_FROZEN` et `UNFROZEN`.
- **Noms de plans :** 18 caractères au plus, définitifs, égaux au nom de la fiche (constaté dans le formulaire en D2-0). **Z8 (« True Cost Calculator Pro », 24 caractères) est donc impossible.**

## 5. Arbitrages (options)

### W1. Source de l'offre du marchand

| Option | Effet | Limites |
|---|---|---|
| (a) API Admin seule (`allSubscriptions`, par nom), comme aujourd'hui | Aucune dépendance nouvelle ; prouvée en D2-0 | Non documentée pour App Pricing après avril 2026 : Shopify peut la couper sans préavis, et avec elle le cron des relances |

## 8. Résultat des vérifications V1 et V2 (2026-09-26, GO de Mathys)

- **Partner Dashboard (V1).** La boutique tcc-tarif-test est trouvable : page de la boutique, historique des événements de TCC Tarification test, « Applications installées », « Crédits d'application : Envoyer ». En revanche, **aucune option « Trial extension »**, ni sur la page de la boutique, ni sur l'aperçu de l'app (statut « Brouillon »). Causes possibles, non départagées :
  - l'app est en brouillon ;
  - elle a été créée dans le Dev Dashboard ;
  - la boutique est de développement.
- **Mutation `appSubscriptionTrialExtend`** : un seul appel, API Admin 2026-07, session de l'app de test, abonnement Pro `75694145750`, `days: 31`.

| | Avant | Réponse de la mutation | Relu après |
|---|---|---|---|
| `trialDays` | 14 | **45** | **45** |
| `currentPeriodEnd` | 2026-10-10 14:38:21 UTC | **2026-11-10 14:38:21 UTC** | **2026-11-10 14:38:21 UTC** |
| `status` | ACTIVE | ACTIVE | ACTIVE |
| `userErrors` | — | aucun | — |

**Conclusion.** Une app en **App Pricing peut prolonger l'essai** d'un abonnement en cours par l'API Admin. Les jours **s'ajoutent** à l'essai (14 + 31 = 45) sur le même abonnement : aucun nouvel abonnement n'est créé, et le marchand n'a rien à approuver. Le plafond de 45 jours de Y6 est donc atteignable.

W3 = (b) reste la décision. La mutation sert de solution de repli prouvée, par exemple par un script manuel lancé sur GO pour un testeur donné, si le Partner Dashboard ne propose pas l'option.
